# Torque Tak!

볼트 사양과 체결 조건에서 권장 체결토크를 내고, 그 체결부가 성립하는지까지 한 화면에서 검토하는 모바일 우선 정적 웹 애플리케이션입니다.

## 주요 기능

**입력**

- 사양 문자열 파싱 — `M5-12`, `M6 접시 20`, `M8x1.25 저두 25` 처럼 한국어·영문 머리 형상 표기를 함께 인식. 소수점 쉼표(`M2,5-10`)도 읽습니다
- 호칭경 M1.6~M24 중 ISO 261 표에 있는 16개, ISO 261 세목 피치, 볼트 길이 — 표에 없는 호칭경(M3.5 등)·피치(`M5×12`처럼 길이를 `×`로 적은 경우 포함)는 오류로 알립니다
- 볼트 강도구분(12.9 · 10.9 · 8.8 · A2-70, ISO 898-1 · ISO 3506-1 최소값), 목표 축력(% 항복)
- 탭 모재 10종, 머리 형상 5종, 마찰 조건(VDI 표 A5 등급) 6종, 와셔 4종(평·대형·스프링), 나사 고정제 7종
- 암나사 물림 깊이 Le와 볼트 길이 — 슬라이더 두 개로 조절
- 선택 입력: 작용 하중(**볼트 1개** 기준, 축방향 인장 / 횡방향 전단), 비나사부 길이 + 해석 수준 3단계

**출력**

- 권장 체결토크와 토크렌치 오차·마찰 산포를 반영한 실제 축력 범위
- 달성 축력 · 항복 이용률 · 예상 파단 토크
- 체결부 단면도 — 물린 나사산 수, 지배 파괴 모드, 비나사부 간섭, 좌면 압괴, 치수선
- 검토 항목 최대 17개와 종합 판정, 설계 NG일 때는 항목별 대응 방법. 판정에 들어가지 않는 정보 항목(산포 상한 이용률)은 따로 표시
- 나사 고정제를 쓸 때 분해에 필요한 토크(체결 마찰분 + 고정제 이탈분)
- 계산 근거 — 단계별 수식과 **근거 등급 배지**(공식 규격 / VDI 2230 / 제조사 TDS / 자체 경험값)
- 사내 시험 대조 — 파단 토크(5회 평균) 편차와 **사내 권장 체결 토크 대조**, 기록되지 않아 가정으로 채운 항목 표기

**동작**

- 별도 설치·빌드 없이 브라우저에서 실행
- 마지막 설정을 자동 저장(`localStorage`)해 새로 고쳐도 이어서 씀
- 모바일 1열 / 태블릿·데스크톱 2열 반응형, 키보드 조작과 스크린리더 지원
- 1열에서는 **물림 깊이 Le가 검토 항목보다 먼저** 옵니다 — Le가 판정 대부분을 좌우하므로 맞추고 나서 읽는 순서입니다. 2열에서는 두 카드가 나란히 놓여 순서가 무의미하므로 좌·우 배치를 유지합니다

## 계산 모델

| 단계 | 식 | 근거 |
| --- | --- | --- |
| 유효단면적 | `As = π/4 · (d − 0.938194p)²` | ISO 898-1 · ISO 261 |
| 강도 | Rp0.2 · Rm 최소값 (8.8: d≤16 640/800, d>16 660/830 · 10.9: 940/1040 · 12.9: 1100/1220) | ISO 898-1 · ISO 3506-1 |
| 체결토크 | `M = F · [0.16p + 0.58·d₂·μG + (D_Km/2)·μK]` | VDI 2230 · 표 A5 마찰등급 |
| 좌면 마찰 지름 (D_Km) | `(머리 좌면 dw + 내경)/2` — 와셔가 있어도 머리 기준, 내경만 와셔 내경 | ISO 4762 dw · 7380-1 · 7089 |
| 비틀림 성분 | 나사부 토크 비율 = 앞 두 항 ÷ 세 항 합 | 체결토크식에서 직접 |
| 조합응력 (체결 상태) | `σred = √(σ² + 3(0.75τ)²)`, τ = MG / (π·dS³/16) | VDI 2230 FMzul 식의 3/2 계수 |
| 조합응력 (사용 상태) | `σred,B = √(σz² + 3(0.5τ)²)` — 외력 포함 볼트 응력 | VDI 2230 kτ = 0.5 |
| 나사산 뽑힘 | `min(0.875·π·d, 0.75·π·D₁) · Le · 0.65` — 암나사·수나사 중 약한 쪽 | VDI 2230 R8 산형에서 유도, 0.65는 자체 경험값 |
| 축력 산포 | 하한 `F/1.3` · 상한 `F/0.7` — 작용 하중은 하한, 뽑힘·면압은 상한 | 토크계수 ±30% |
| 머리 내력 (접시·버튼) | 파단 하중 × `0.80` | ISO 10642 NOTE 2 — 전 등급 공통 |
| 조임 축력 (접시·버튼) | 목표 축력 × `0.52` | 제조사 공표값 (Unbrako·Bossard·Hobson) |
| 좌면 면압 | 축력 상한 ÷ 좌면 면적. 와셔는 `d_W + 1.6·h`(와셔 외경 상한)로 확산 (좌면 재질 = 탭 모재 가정) | VDI 2230 한계 면압 · 와셔 확산 근사 |
| 체결 두께 | `Lk = 볼트 길이 − Le` — 접시는 카운터싱크도 판재의 일부 | 기하 |
| 부재·볼트 강성 | δS 구간 분해(원통 구간 기준) + δP Rötscher 30° 원추 | VDI 2230 · Shigley |
| 분해 토크 | `Tfric = F(K·d − p/π)` + 고정제 이탈분 | Henkel TDS (ISO 10964) |

좌면 지름은 상수 배수가 아니라 규격 표에서 옵니다. 표준머리는 머리 외경 dk가 아니라 **좌면 지름 dw**(ISO 4762 dw min)를 씁니다 — dk를 쓰면 M10에서 좌면 면적이 18% 넓게 잡혀 면압이 15% 낮게 나옵니다. 버튼머리는 ISO 7380-1 dk(M3~M5 1.90d, M6부터 1.75d)에 0.94를 곱해 dw를 근사합니다(원표 대조 필요).

**와셔는 마찰과 면압을 다르게 바꿉니다.** 미끄럼은 마찰 모멘트가 작은 계면에서 일어나므로 머리는 와셔 위에서 돕니다 — 그래서 D_Km은 와셔가 있어도 머리 좌면 dw에서 오고, 와셔는 내경만 바꿉니다. 와셔 외경은 판재 면압에만 들어가며, 그것도 외경 전체가 아니라 하중이 와셔 두께만큼 퍼진 지름 `d_W + 1.6·h`(와셔 외경이 상한, VDI 2230 와셔 근사 — 원표 대조 필요)까지입니다. 와셔 외경을 D_Km에 넣으면 대형 와셔에서 토크가 20~25% 높게 나와, 그 토크를 실제로 걸면 축력이 그만큼 더 들어갑니다.

**물릴 나사부가 0이면 권장 토크를 내지 않습니다.** 접시 머리보다 짧은 볼트, 비나사부가 나사부를 다 먹은 볼트는 축력을 만들 수 없으므로 토크 자리에 `—`가 오고 설계 NG가 됩니다.

체결토크는 VDI 2230의 세 항 분해식으로 구하고, 마찰계수 μ는 **표 A5 마찰등급**에서 옵니다. 관행식 `T = K·F·d`의 등가 K도 함께 표기하지만 계산에는 쓰지 않습니다 — **K와 μ는 같은 숫자가 아니기 때문**입니다. 피치 성분 `0.16p`가 K 안에 이미 들어 있어 `K 0.20`은 `μ 0.20`이 아니라 `μ 0.145`에 해당하고, 그건 VDI 기준으로 무윤활이 아니라 가볍게 윤활된 B등급 표면입니다. 탈지 후 건식으로 조립하는 가공면은 C등급(`μ 0.14~0.24`)이라 기본값을 `μ 0.18`로 둡니다.

마찰계수가 높으면 비틀림이 볼트 용량을 더 먹으므로 **걸 수 있는 축력이 줄어듭니다** — 이용률 90%(VDI 체결 상태)에 해당하는 목표 축력이 M10에서 몰리브덴 84%부터 스테인리스 건식 69%까지 내려갑니다. 이 앱의 이용률은 VDI 2230 FMzul 식과 0.1pt 안에서 일치합니다(M6·M10·M16 × μ 6종 대조). 목표 축력 옵션의 판정이 마찰 조건에 따라 달라지는 것은 이 때문입니다.

토크법의 산포(±30%) 때문에 **상한 쪽 볼트는 거의 모든 목표 축력에서 항복을 넘습니다**(M10 건식 65%도 상한에서 114%). 상시 참에 가까운 사실이라 판정으로 세우지 않고 정보 항목으로 보입니다. 대신 작용 하중 검토는 하한 축력, 뽑힘·면압은 상한 축력에서 합니다.

나사산 변형 보정 0.65 · 저두 머리 계수 0.50 · 뽑힘 안전율 1.4(산포 상한 축력 기준 — 공칭 축력 기준 2.0과 같은 경계)는 규격 근거가 없는 자체값입니다. 그중 **저두 0.50이 가장 얇습니다** — 사내 M10 저두 파단 실측 1점에 맞춘 값입니다(0.60이던 값을 내렸습니다. 0.60에서는 권장 토크와 실측 파단 사이 마진이 1.29배로, 다른 머리 형상의 1.6~2.6배보다 확연히 좁았습니다). 앱 안의 **계산 근거** 패널이 단계마다 이 구분을 표기하며, **모델 한계** 패널에 적용 범위 밖 조건을 적어 두었습니다.

접시·버튼머리는 규격이 강도구분을 제한하지 않습니다 — ISO 10642 · ISO 14581 · JIS B 1194 모두 12.9를 포함하고, 규격이 하는 일은 **머리 내력을 나사부의 80%로 제한**하는 것입니다. 따라서 선택한 등급을 낮추지 않고, 12.9를 고르면 수소취성과 육각홀 한계를 주의로 알립니다. 조임 축력 감액 0.52는 제조사 공표값입니다. 강도를 공칭값(10.9: 900 MPa · 12.9: 1080 MPa)으로 쓰던 때 이 조합은 Bossard 감액 토크표(010.9, M3~M12)와 ±2%, Hobson 012.9 토크표와 ±1% 안에서 일치했습니다. ISO 898-1 최소값으로 바꾼 뒤에는 10.9가 약 +4%, 12.9가 약 +2% 올라가므로 두 표와 다시 대조해야 합니다.

**스프링 와셔는 치수만 반영합니다.** 적정 축력으로 조이면 완전히 눌려 평와셔와 같아지므로 이완 방지 효과를 모델에 넣지 않았습니다 — NASA 체결 설계 지침과 Junker 횡진동 시험이 모두 평와셔 대비 효과가 없다고 봅니다. 판재 면압에는 DIN 127 B 외경(약 1.75d)을 상한으로 두께만큼 퍼진 지름을 쓰고(마찰 지름은 다른 와셔처럼 머리 좌면 기준), 고정제 같은 실제 이완방지 수단이 없으면 검토 항목이 그 사실을 알립니다.

적용 범위 밖은 앱이 직접 알립니다 — **수지 탭**(크리프·응력완화가 지배해 정적 전단 모델이 성립하지 않음), **박판·소수 나사산**(판재 함몰·찢김이 지배), **접시머리 원추 좌면**(면압 미검토, 와셔를 골라도 좌면이 되지 못하므로 계산에서 제외). 강도구분은 ISO 898-1 최소값을 씁니다 — 8.8은 호칭경에 따라 갈려 d>16에서 830/660 MPa입니다. 볼트가 모재보다 약하거나(A2-70) 모재가 볼트보다 강하면(SCM440) **수나사 쪽이 먼저 뽑힐 수 있어** 암나사·수나사를 함께 검토합니다.

> 계산 결과는 설계 검토를 돕기 위한 참고값입니다. 토크로는 축력을 정밀 제어할 수 없어 실제 축력은 ±30% 흩어집니다. 안전이 걸린 체결부는 축력계·각도법·연신법으로 검증하고, 실물 시험으로 확정하십시오.

### 볼트 길이와 토크의 관계

볼트 길이는 강도를 직접 지배하지 않습니다. 지배하는 것은 유효단면적·강도구분과 실제 물림 깊이 Le입니다. 다만 **볼트가 짧아 판재 두께를 0으로 놓아도 필요한 물림에 닿지 못하면**, 그 길이가 곧 뽑힘 여유의 상한이 됩니다. 이 경우에만 길이를 바꾸면 권장 토크가 함께 움직이고, `볼트 길이 여유` 검토 항목이 그 사실을 알려줍니다. 물림이 넉넉한 구간에서 길이를 바꿔도 토크가 그대로인 것은 정상입니다.

## 프로젝트 구조

```text
torque-tak/
├─ index.html              # 앱 진입점과 화면 마크업
├─ assets/
│  ├─ css/
│  │  └─ styles.css        # 레이아웃, 컴포넌트, 반응형 스타일
│  └─ js/
│     └─ app.js            # 제원 테이블, 계산식, 상태 관리, 화면 동작
└─ README.md
```

`app.js`는 세 층으로 나뉩니다.

1. **제원 테이블** — 피치, 강도구분, 머리 형상, 모재, 고정제, K값, 와셔
2. **`compute()`** — DOM에 손대지 않는 순수 함수. 입력 객체 하나를 받아 계산값과 검토 항목 배열을 돌려줍니다
3. **`render()`** — `compute()` 결과를 화면에 씁니다. 드래그 중에는 `render(true)`로 무거운 작업을 건너뜁니다

## 실행 방법

빌드 과정이나 패키지 설치가 필요하지 않습니다.

### 로컬 서버로 실행 (권장)

```bash
python -m http.server 8000
```

또는:

```bash
npx serve .
```

기본 접속 주소는 `http://localhost:8000`입니다.

### 파일로 바로 실행

`index.html`을 브라우저에서 열어도 동작합니다. 단 `file://`에서는 브라우저에 따라 `localStorage`가 막히거나 파일 위치별로 따로 저장되어 설정이 이어지지 않을 수 있습니다.

## 배포

**계산값이 바뀌는 수정(제원표·계수·식·판정 기준)을 배포할 때는 `index.html`의 캐시 토큰 `?v=YYYY-MM-DD`를 반드시 배포일로 올립니다.** 빌드가 없어 파일명이 고정이라, 토큰을 그대로 두면 기존 방문자는 캐시된 옛 `app.js`로 옛 숫자를 계속 봅니다. `styles.css`와 `app.js`는 같은 토큰을 씁니다(현재 `2026-10-20.3`).

모든 리소스가 상대 경로를 쓰고 외부 의존성이 없으므로 GitHub Pages, Netlify, Vercel 등에 별도 빌드 없이 배포할 수 있습니다.

GitHub Pages를 쓰는 경우 저장소의 **Settings → Pages**에서 배포 소스를 `main` 브랜치의 `/(root)`로 선택하세요.
