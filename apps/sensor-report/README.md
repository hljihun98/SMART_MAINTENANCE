# 센서 보고서

PARKIE 로봇의 LiDAR·카메라 센서 점검 결과와 사진을 작업 단계별로 기록하고 PDF 보고서를 생성합니다.

## 주요 기능

- 점검 대상 센서 4개: FRONT LIDAR, REAR LIDAR, FRONT CAMERA, REAR CAMERA
- 작업 단계 4개: 작업 전 / 이동 전 / 작업 후 / 이동 후 — 단계마다 결과·메모·사진·전체 상태를 따로 기록
- 센서별 결과: **정상 / 이상** (이상이면 내용 메모)
  - 메모가 있는 '이상'을 해제하면 메모가 지워지므로 확인창을 띄움
- 센서별 사진 (단계마다)
  - FRONT LIDAR 4장: 정면·좌측·우측·상면
  - REAR LIDAR 4장: 정면·좌측·우측·후면
  - FRONT/REAR CAMERA 각 2장: 정면·측면
- 호기 전체 상태(단계별): 정상 / 경미한 손상 / 교체 필요 / 긴급 점검
  - 센서에 이상이 있으면 '경미한 손상', 모두 정상이면 '정상'으로 자동 설정
  - 자동 설정은 심각도를 올리기만 하며, 사용자가 직접 고른 더 심각한 값은 덮어쓰지 않음
  - 미선택은 '정상'으로 바꾸지 않고, PDF 생성 시 확인창에서 경고(PDF에는 '미선택'으로 표시)
- PDF 보고서 생성 (jsPDF, 선택한 단계 기준)
  - 한글은 Canvas에서 PNG로 변환해 삽입
  - 사진 칸마다 해당 센서의 실제 촬영 각도를 표시
  - 사진은 긴 변 800px로 줄여서 삽입
  - 긴 메모는 '…'로 줄임 표시, 머리글의 호기 상태 목록은 자동 줄바꿈
  - 생성하는 동안에는 입력이 잠기며, [PDF 생성]을 누른 시점의 단계·호기 데이터로 만듦(도중에 바뀐 내용이 섞이지 않음)
- 반응형 UI (현장 스마트폰 사용 최적화)
- 서버 저장(Supabase)은 **추후 연동 예정, 현재 비활성** — '서버 저장 (준비 중)' 버튼은 안내 알림만 표시

## 데이터 저장

모든 데이터는 이 기기의 브라우저에만 저장됩니다.

| 위치 | 이름 | 내용 |
|---|---|---|
| localStorage | `parkie_sensor_v3` | 점검 상태 JSON (사진 본문 없음, 사진 id만) — `schema: 4` |
| IndexedDB | DB `parkie_sensor_photos` / store `photos` | 사진 원본. key = 사진 id, 값 = JPEG `Blob` (Blob 저장이 안 되는 브라우저는 dataURL 문자열) |
| localStorage | `parkie_sensor_v3_corrupt_backup` | 저장 데이터가 손상되어 읽을 수 없을 때만 생성되는 원본 백업 |

- **예전 형식 데이터 자동 변환**
  - 예전 버전은 사진을 base64로 localStorage에 직접 저장했습니다(`schema` 필드 없음).
  - 이런 데이터를 처음 열 때 사진을 IndexedDB로 옮기고, localStorage에는 사진 id만 남깁니다.
  - 같은 사진은 한 번만 저장하고 id를 공유합니다.
  - 옮기지 못한 사진은 원본(base64)을 그대로 두고, 다음 실행 때 다시 시도합니다.
- **저장 실패 경고**
  - 저장 공간 부족 등으로 저장에 실패하면 화면 상단에 경고를 표시합니다.
  - 경고는 문제가 해결될 때까지 계속 남아 있습니다.
  - 사진 저장에 실패하면 그 사진은 첨부하지 않습니다.
- **다른 창에서 데이터를 지운 경우**
  - 포털 → 데이터 관리 등에서 데이터를 지우면, 열려 있는 앱은 데이터를 되살리지 않도록 자동 저장을 멈춥니다.
  - 이때 새로고침하라는 안내를 표시합니다.
- **다른 탭에서 데이터를 바꾼 경우**
  - 같은 앱을 여러 탭(창)에서 열어 두고 한쪽에서 저장하면, 다른 탭은 이전 내용으로 덮어쓰지 않도록 자동 저장을 멈추고 새로고침 안내를 표시합니다.
- **사진 정리**
  - 앱을 열 때 어디에서도 참조하지 않는 사진(저장 실패 등으로 남은 것)을 사진 저장소에서 정리합니다.
  - 다른 탭이 열려 있으면(Web Locks로 확인) 정리를 건너뜁니다. Web Locks를 지원하지 않는 브라우저에서는 정리하지 않습니다.
  - 손상 데이터 백업(`parkie_sensor_v3_corrupt_backup`)이 참조하는 사진은 지우지 않습니다.
- **초기화 버튼**: localStorage 상태와 IndexedDB 사진을 모두 지웁니다.

## 아키텍처 노트

- 단일 파일 앱: HTML·CSS·JS가 모두 `index.html` 안에 있습니다.
- jsPDF는 CDN이 아니라 저장소에 포함된 `../../assets/vendor/jspdf-2.5.1.umd.min.js`를 사용합니다(오프라인 동작).
  - 불러오지 못하면 상단 경고와 PDF 버튼 안내로 원인을 알려줍니다.
- `LOGO_SRC`(`../../logo.png`): 상단바와 PDF 머리글 로고입니다.
- 사진 key 형식은 `호기id_센서번호_각도번호_단계key`입니다.
  - 단계 key에 `_`가 들어 있으므로(`move_before`) `parsePhotoKey()`로만 해석합니다.
- `textToPng()` / `pdfWrappedText()`: 한글 텍스트를 Canvas PNG로 변환해 PDF에 넣습니다.
- Supabase 연동 코드는 주석 처리된 상태로 보존되어 있습니다(추후 연동 예정).
  - 연동 시 사진은 `photoStore.get(id)`로 Blob을 읽어 업로드해야 합니다.
